# FUTURE_CS_02
## Phishing Email Detection & Awareness System
Future Interns Cyber Security Internship Task 2
## About the Project
This project is about analyzing phishing emails and identifying the signs that can help users recognize them.
I analyzed three fictional phishing email examples based on common phishing situations:
- An account lock warning
- A fake delivery notification
- An unusual login alert

I looked at the sender information, subject, email content, URLs, and different social engineering techniques used in each email. I then classified the risk and explained what a user should do if they receive a similar email.

## Objectives
The main objectives of this project were to:

- Identify common signs of phishing emails.
- Analyze suspicious email content and links.
- Classify the risk of each email.
- Understand how attackers use urgency and fear to influence users.
- Explain phishing risks in simple language.
- Create useful awareness and prevention guidelines.

## Analysis Method

I used the following steps to analyze each email:

1. Checked the sender information.
2. Examined the subject line.
3. Read the email content for suspicious requests or language.
4. Examined the URLs without opening suspicious links.
5. Identified phishing indicators.
6. Classified the email based on the findings.
7. Added recommendations for how a user should respond.

I considered multiple indicators together instead of deciding that an email was phishing based on only one sign.

## Main Phishing Indicators Found

Some of the main warning signs I identified were:

- Urgent or threatening language
- Fear-based messages
- Suspicious sender domains
- Generic greetings
- Suspicious URLs
- Requests to verify account information
- Short deadlines
- Threats of account restriction
- Requests for personal or financial information

## Prevention Tips

Users should:

- Check the sender's email address carefully.
- Be careful with emails that create urgency or fear.
- Avoid clicking suspicious links.
- Access accounts directly through the official website or application.
- Never provide passwords or OTPs through unexpected emails.
- Be careful with unexpected payment requests.
- Report suspicious emails to the appropriate security or IT team.
- Avoid opening unexpected attachments.

The suspicious URLs included in the examples were not opened.

## Conclusion

This project helped me understand how phishing emails use social engineering to convince users to take unsafe actions. The main lesson from the analysis is that users should not act immediately when an email creates fear or urgency. Important requests should always be verified through a trusted and official source.
